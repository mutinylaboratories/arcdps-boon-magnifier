# Gw2-64.exe: where buffs live (RE notes)

Analysed 2026-09-19 from the Binary Ninja project `C:\Projects\gw2_re\gw2.bnpr`
(`tools/binja/annotate_gw2.py` writes these names/types into the database).
Addresses are for that build only; the *patterns* (assert strings, call shapes) are what
to search for after a patch. Scope: the local player's own buff bar.

## The chain to your own buff bar

```
Contexts_GetThreadLocal()            0x1409b4cd0  TLS slot -> context table
   +0x98  ChCliContext
       ->vtable[0x68/8]()            GetControlledCharacter()
           ->vtable[0x108/8]()       GetCombatant()
               ->vtable[0x40/8]()    CmbtCliBuffBar*
```

`CmbtCliBuffBar` (Game\Combat\Cli\CmbtCliBuff.cpp):

| offset | field | notes |
|---|---|---|
| +0x20 | `buffsCapacity` (u32) | `m_buffs` open-addressing hash map |
| +0x24 | `buffsCount` (u32) | |
| +0x28 | `buffsTable` | array of 0x18-byte slots `{u32 key; u32 pad; CmbtCliBuff* buff; u64 occupied}` |
| +0xb0 | `listener` | vtable +0x120 activated / +0x130 deactivated / +0x138 duration changed (UI notify) |
| +0xd8/+0xe4 | status array / count | 12-byte `{i32, i32, u32 buffId}` sorted entries |

`CmbtCliBuff` (0x78 bytes, one per stack/instance):

| offset | field | notes |
|---|---|---|
| +0x08 | `skillId` | copied from `skillDef+0x28`; Stability = 1122 |
| +0x10 | `skillDef` | content def; `GetBuff()` ⇔ `+0x58 == 1 && +0x60 != 0` |
| +0x18 | `buffId` | instance id, map key; equals arcdps' trackable id |
| +0x28 | `sourceAgent` | applier |
| +0x40 | `durationMs` | |
| +0x44 | `startTimeMs` | `GetTimeMs()` (0x1409ce250) at (re)activation |
| +0x4c | `isActive` | remaining = `start + duration - now` when 1 |

Stability stacks by intensity, so expect several `CmbtCliBuff` with `skillId == 1122`;
the overlay's "time left" is the max remaining over them.

## Network message handlers (Game\Combat\Cli\CmbtCliMsg.cpp)

No static callers (dispatch table). All: `(void* ctx, msg*)`, `msg+2` = target agent id,
combatant via `CmbtCliContext_GetCombatantByAgentId(ctx+0xb8, agentId)`.

| line | handler | payload | effect |
|---|---|---|---|
| 0x21 | `CmbtCliMsg_BuffActivate` 0x1412c25d0 | `{+6 buffId, +0xa remainingMs}` | `isActive=1`, start recomputed |
| 0x30 | `CmbtCliMsg_BuffApply` 0x1412c2640 | `{+6 srcAgent, +0xa skillId, +0xe buffId, +0x12 durationMs, +0x16 u8, +0x17 isActive}` | `AddBuff` |
| 0x4c | `CmbtCliMsg_BuffDeactivate` 0x1412c2750 | `{+6 buffId, +0xa newDurationMs}` | `isActive=0` |
| 0x5b | `CmbtCliMsg_BuffSetDuration` 0x1412c27c0 | `{+6 buffId, +0xa newDurationMs}` | duration change (extension) |
| 0x6a | `CmbtCliMsg_BuffRemoveByKey` 0x1412c2830 | `{+6 agent, +0xa key}` | removes all matching (bulk strip) |
| 0x7b | `CmbtCliMsg_BuffRemove` 0x1412c28c0 | `{+6 srcAgent, +0xa buffId}` | removes one instance |
| 0x8c | `CmbtCliMsg_BuffStatusBatch` 0x1412c2950 | count + pairs | status array insert |
| 0xa0 | `CmbtCliMsg_BuffStatusRemove` 0x1412c29f0 | `{+6 buffId}` | status array remove |

These map 1:1 onto arcdps' BUFFAPPLY / BUFFACTIVE / BUFFDEACTIVE / BUFFCHANGE /
BUFFREMOVE events, which arcdps then holds for ~2.65 s.

## Two ways to feed `realtime_report`

1. **Poll (no hooks, works under plain arcdps too):** each frame walk the chain above,
   iterate `buffsTable`, collect entries with `skillId == 1122`, report
   `active = any`, `stacks = count`, `remaining = max(start+duration-now)` (use
   `GetTimeMs` for `now`, or `timeGetTime()` if it proves to be the same clock).
   Needs signatures for: `Contexts_GetThreadLocal` (or its TLS index global) and the
   three vtable slot indices (stable across patches far more often than addresses).
2. **Hook** `CmbtCliMsg_BuffApply` / `BuffRemove` / `BuffRemoveByKey` / `BuffDeactivate`
   and compare `msg->targetAgentId` with the local player's agent id. Event-driven, but
   needs MinHook (Nexus) and exact prototypes: all four are `int64_t (void*, void*)`.

Implemented: (1), in `src/plugin/realtime_gw2.cpp`. The three virtual calls were resolved
to plain field reads (`GetControlledCharacter` = `*(ChCliContext+0x98)` gated on bit 4 of
`character+0x178`; `GetCombatant` = `character+0x40`, embedded; `GetBuffBar` =
`*(combatant+0x90)`), and `GetTimeMs()` is `timeGetTime()`, so the whole chain is memory
reads guarded by `safe_read`. The only per-build signature is `[contexts_tls_index]`
(the TLS index global read by `Contexts_GetThreadLocal`), generated by
`tools/binja/targets_gw2.py`.

## Anchors for re-finding after a patch

- String `!m_buffs.Find(buffId)` → `AddBuff`; its single caller is `BuffApply`.
- String `!buffData->isActive` → `ActivateBuff`; its caller is the line-0x21 handler.
- All eight handlers reference the `CmbtCliMsg.cpp` path string and call the same
  combatant lookup as their first call.
- `m_controlledCharacter` strings live in UI code; the getter is `ChCliContext` vtable
  slot 13 (`+0x68`) — verify via any `CharClientContext()->GetControlledCharacter()` assert.

## Skill bar (Game\Char\Cli\ChCliSkillbar.cpp, CharSkillbar.cpp)

Used to gate the pulsing-field projection: a field skill that is on the bar and not
recharging is "armed", so its first stability pulse is treated as the cast.

```
character + 0x520            ChCliSkillbar*
  + 0x1d0                    skillDef*[23] slot skill defs (CHAR_SKILLBAR_SLOTS = 0x17)
  + 0x150                    CharSkillbar recharge manager*  (pointer, not embedded)
      + 0x24  u32            time base (game-relative clock, NOT timeGetTime)
      + 0x30  float          recharge rate multiplier (alacrity)
      + 0x48                 intrusive list head; low bit set / null = end
          entry + 0x08       next
          entry + 0x10 i32   remaining ms at the time base (-1 = none); entries are dropped when done
          entry + 0x18       skillDef*  (skillDef + 0x28 = skill id)
          entry + 0x24 u32   kind, 0 = skill recharge
```

Measured with Hallowed Ground (skill 9253, 48 s recharge): the first stability pulse
lands at cast *start*; the recharge entry appears at cast *end*, ~1 s later. So the
recharge is a good "is it on cooldown" signal but a poor cast trigger, which is why the
projection keys off the first pulse instead. Stand Your Ground appears to be 9084.
